Three Roads: Choose Your Stack with AI

The portfolio needs readable case-study copy, links to notebook evidence, and one interactive checker. The build should use a free host, stay simple to update, and avoid storing visitor inputs.

OptionBuild and hostTrade-off
No-code builderUse a Carrd single page and its hosted URL. No backend for the basic page.Quick for text and links. Adding and testing an interactive calculator is less straightforward than keeping the code in the repo.
Static HTML, CSS, JavaScriptHost ordinary files on GitHub Pages. The checker runs in the browser.Easy to show real evidence and maintain a simple feature. As the site grows, repeated markup may make adding cases slower.
Static site frameworkBuild an Astro site and publish its generated static files on GitHub Pages. No backend is necessary at launch.Useful templates for many cases, with an extra build step and dependencies to maintain.

Choice. Static HTML, CSS, and JavaScript. I can explain each file and add a case by editing a section and linking its evidence. The front-runner would need additional infrastructure if I later wanted a contact form that delivers messages or any stored data. The current portfolio displays the study and runs one local calculation, so there is no backend to maintain.

Make It Do Something

Run the search-decline checker. The browser reads the two counts when the form is submitted. JavaScript checks the inputs, applies the study’s eligibility and material-loss thresholds, and updates the result below the form.

A backend is a server that processes requests or holds shared data. This feature needs neither. The demo sends no impression counts to a server and applies the rule to example counts. It does not run the trained model.
